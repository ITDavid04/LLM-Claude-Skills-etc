# Prüfliste vor der Abgabe

Gehe die Liste durch, bevor du den Text ausgibst. Sie ist nach Gewicht geordnet: Fachliche Fehler kosten am meisten, Stilfehler am wenigsten.

## 1. Fachlich

- [ ] Jeder Code im Text wurde ausgeführt. Die gezeigte Ausgabe stimmt mit der echten Ausgabe überein.
- [ ] Kein Beispiel widerspricht der Lektion, die es zeigt. Beispiel aus dem Material: Ein Event heißt `PizzaGebacken` (Vergangenheit, Tatsache), der zugehörige Listener druckt aber „wird jetzt gebacken" (Gegenwart). Das untergräbt die Lehre „Events sind Fakten".
- [ ] Wo ein Beispiel ein echtes Verfahren nur nachahmt, steht das in einem Satz im Text („Hier simulieren wir die Datenbank-Transaktion mit try/except").
- [ ] Zu jedem Bild steht, wo es hinkt.
- [ ] Definitionen, Zahlen, Befehle und Prüfbegriffe sind unverändert genau, unabhängig vom lockeren Ton.
- [ ] Es wurde keine Zahl, Quelle oder Behauptung ergänzt, die weder im Quellmaterial noch beim Nutzer steht.
- [ ] Unbelegte Aussagen sind entweder belegt, abgeschwächt oder gestrichen.

## 2. Zusammenhang

- [ ] Querverweise stimmen: Teil-Nummern in Teasern, Verweise auf frühere Texte, Namen von Begriffen.
- [ ] Bei einer Reihe: Die Übersicht verspricht genau die Themen, die die Texte behandeln.
- [ ] Das Abschlussmotiv aus der Weltbibel ist in allen Texten dasselbe (nicht Schaufel hier, Schürze dort).
- [ ] Ein einmal gesetzter Begriff wird nicht durch Synonyme ersetzt.
- [ ] Jeder Text ab Nummer 2 enthält mindestens einen benannten Rückgriff. Text 1 enthält keinen Pflichtrückblick.

## 3. Reste und Doppelungen

- [ ] Keine Anrede an einen Chat-Nutzer („Das freut mich riesig!", „Da du Anfänger bist").
- [ ] Keine Hinweise auf Modus, Level oder Prompt im fertigen Text.
- [ ] Kein Angebot am Ende („Wenn du magst, …", „Soll ich noch …?").
- [ ] Keine rhetorischen Schlussfragen an einen Leser, der nicht antworten kann.
- [ ] Keine doppelten Absätze, Zitate oder Teaser aus zusammenkopierten Entwürfen. Suche gezielt nach wiederholten Sätzen.
- [ ] Keine verwaisten Zeilen („Zusatz: …" ohne Zusammenhang).
- [ ] Keine Pflichtblöcke ohne Inhalt.

## 4. Aufbau und Aufgaben

- [ ] Jeder Abschnitt beginnt mit einer Szene oder einem Problem, nicht mit einer Definition.
- [ ] Reihenfolge Bild, Begriff, Definition, Grenze des Bildes, Aufgabe ist erkennbar.
- [ ] Jede Aufgabe ist konkret, machbar und baut auf der vorherigen auf.
- [ ] Der Nachweis ist greifbar. Das Erfolgskriterium ist genannt, wenn Fehlinterpretation naheliegt.
- [ ] Reihenfolge und Länge der Blöcke wechseln zwischen Texten, es gibt kein starres Template.

## 5. Stimme

- [ ] Eine Anrede im ganzen Text: du.
- [ ] Verben statt Substantivketten. Die Satzlänge wechselt.
- [ ] Kein „nicht X, sondern Y", keine Dreierlisten aus Gewohnheit, kein „der Schlüssel", „im Kern", „das Herz der Sache".
- [ ] Kein Satz steht nur da, um Gewicht zu geben. Jeder bringt etwas Neues.
- [ ] Höchstens ein Modalpartikel pro Satz.
- [ ] Humor höchstens ein- bis zweimal pro Abschnitt, nie in Definitionen oder Warnungen, nie auf Kosten des Lesers.
- [ ] Kein Zuspruch auf Vorrat („Du schaffst das!").

## 6. Format

- [ ] Keine Emojis. Weder in Überschriften noch im Text noch in Code-Ausgaben oder `print`-Zeilen.
- [ ] Schlichte Überschriften. Fließtext überwiegt, Tabellen nur für echte Vergleiche.
- [ ] Code in Codeblöcken mit Sprachangabe, die erwartete Ausgabe darunter.
- [ ] Wenn eine andere Skill oder der Nutzer ein Format vorgibt, ist es eingehalten.

## Wenn etwas nicht stimmt

Bei einem fachlichen Fehler im Quellmaterial: Nicht stillschweigend korrigieren und nicht stillschweigend übernehmen. Melde ihn dem Nutzer mit Fundstelle und Vorschlag, und schreibe den Text mit der korrigierten Version, sofern der Nutzer das möchte.

Bei fehlenden Informationen: Schreibe einen einfacheren Satz oder frage einmal gezielt nach. Erfinde nichts.
